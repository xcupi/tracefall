# Real-lab validation baseline — 2026-10-18

## Verdict

**Partial pass, NOT forensic-analysis acceptance.** All five datasets completed the
local-path server pipeline and produced reports. All 18 raw plugin outputs from
three Windows memory dumps matched an independent invocation of Volatility 3.
However, persisted events lose distinct memory observations through deduplication,
and automatic detection/coverage is insufficient to reconstruct these cases.
A green job means the implemented stages completed, not that the incident was solved.

This is a validation record, not a remediation release. No production code was
changed during this validation. The tested binary was built from HEAD
`b2c6ac90c54c1596ea6ae3b5aeeb8e64ae9f672f` plus the uncommitted item-4 changes;
`tested-build.json` records binary/diff hashes and working-tree status.

- Built and ran the actual Tracefall binary on an isolated loopback server with its
  own database/data directory. Created one case per dataset and submitted actual
  `POST /api/cases/{id}/pipeline/jobs` jobs with `local_path` and analysis enabled.
- Windows: Volatility 3 **2.28.2**, with symbols prepared before sandbox execution.
  The Tracefall runner used **bubblewrap** for all three images. No sample or
  extracted executable was uploaded to VirusTotal or executed.
- Comparison: directly invoked each of pslist, psscan, cmdline, netscan, malfind,
  svcscan separately using Volatility's JSON renderer and `--offline`. Removed
  `__children` from the flat direct rows and compared the complete row multisets
  with Tracefall's combined analysis. **18/18 outputs matched exactly.** This
  validates the wrapper/transport, not Volatility's own forensic correctness.
- Insider: independent **dissect.evidence 3.13** enumerated **1,860 files**, matching
  Tracefall's catalog. Both extracted supported files (Firefox `places.sqlite`
  and `irZLAohL.jpeg`) matched independent SHA-256 values. Dissect's empty-file
  open path raised `struct.error`; the comparison handled known zero-byte entries
  as empty rather than treating that tool exception as image corruption.
- The Crime: queried copies of SQLite databases with their WAL/SHM sidecars (never
  opened source databases writable), hashed the installed APK and inspected the
  ticket/map images. These checks expose unsupported artifacts; they are NOT
  results automatically generated by Tracefall.
- Recomputed the three memory files' and AD1 file's SHA-256 after all work:
  **all unchanged**. All five collection integrity checks returned `verified`.
- All five report ZIPs passed the real `tracefall verify-report` command (exit 0,
  three payload files each). A matching manifest is not a signature or proof of
  analytical correctness. PDFs were generated for every case. Insider page 2 and
  Reveal pages 2–3 were visually inspected, not every page of every report.

## Walkthrough comparisons

### Reveal — key observations present

- `powershell.exe`, PID **3692**, PPID **4120**, created **2024-07-15 07:00:03 UTC**.
- Command line retains `-windowstyle hidden`, WebDAV `45.9.74.32@8888`,
  `davwwwroot` and `3435.dll,entry`.
- PowerShell malfind regions exist in the combined output, but not all survive
  event deduplication (see failure below).
- One PowerShell suspicious-command finding exists. **31 of 32 findings** were
  generic svchost-child lineage findings, not 32 independently validated attacks.
- Username/SID and malware-family attribution were not validated: the implemented
  plugin plan does not include getsids and there was no threat-intelligence lookup.

### Ramnit — process and connection present, weak automatic findings

- PID **4628** has executable path `C:\Users\alex\Downloads\ChromeSetup.exe`.
  This also matches the visible cmdline screenshot in the user's Medium link.
- A connection attempt to **58.64.204.181:5202** is preserved; the source state is
  `SYN_SENT`, which is not evidence of a completed connection.
- All **32 findings** were generic svchost-child lineage findings. The primary
  ChromeSetup lead was available in the timeline but not surfaced as a targeted
  finding. This is an analysis-depth gap, not a failure to parse its process.
- Dumped executable hash, PE timestamp, domain attribution and IP geolocation were
  not produced/validated by this pipeline. Do not substitute walkthrough values
  for locally computed evidence.

### RedLine — core observations present

- `oneetx.exe` PID **5896**; child `rundll32.exe` PID **7732**, PPID **5896**.
- Its malfind region has `PAGE_EXECUTE_READWRITE` and an `MZ` prefix.
- Socket to **77.91.124.20:80** is preserved with state `CLOSED`.
- `Outline.exe` is present. A process name alone does not independently establish
  its VPN activity or prove NIDS evasion.
- The 20 findings were all generic lineage findings, including one for oneetx;
  this is not a dedicated malfind/C2 analysis or malware-family verdict.
- Full oneetx executable path is not recovered from cmdline (Volatility returns
  null there). filescan/strings would be a further path, not something this
  baseline pretends to have recovered.

### Insider — container works; Linux investigation largely unsupported

- Tracefall preserves the **mimikatz_trunk.zip** browser download and its time
  **2019-03-22 03:04:11.609 UTC**, consistent with the walkthrough's download lead.
- `.bash_history`, `auth.log`, `Checklist` and shell scripts are cataloged but

  `binwalk didyouthinkwedmakeiteasy.jpg`, and the myfirsthack directory changes.
  `Checklist` includes `Profit`; `firstscript_fixed` mentions `Young`.
- Empty Apache access.log has the walkthrough MD5
  `d41d8cd98f00b204e9800998ecf8427e`. **Empty access.log does not establish that
  Apache was never started**; do not adopt that walkthrough inference as fact.

  is Windows-style normalized. Those representations should be made OS-aware.
- Insider is a **logical AD1 acquisition**, not a test of Tracefall's E01/raw

## Blocking defects discovered

### P0 — distinct memory observations collapse during event deduplication

`internal/model/dedup.go:40-56` does not include malfind region bounds, service
name or local socket endpoint/protocol in event identity; these memory fields are
stored in Extra, which the generic key excludes. The timestamp is shared for
snapshot observations, so different objects collide.

| Dataset | Distinct raw malfind regions | Persisted malfind events | Distinct nonempty raw service names | Persisted distinct service names |
|---|---:|---:|---:|---:|
| Reveal | 12 | 6 | 654 | 474 |
| Ramnit | 11 | 5 | 651 | 552 |
| RedLine | 3 | 3 | 599 | 271 |

For example, Reveal's five separate PowerShell regions become one event.
The combined analysis JSON retains the rows, but timeline, detection and exports
cannot inspect them as separate events. Network identity also omits local port,
source address and protocol, risking the same collapse for distinct sockets.

A standalone Go probe using the actual parser and `ComputeDedupHash` reproduced
these collisions before persistence. This is not merely Volatility reporting
several copies of the same service: distinct service names disappear.

### P1 — broad lineage noise and missing memory-specific analysis

`internal/detect/rules.go:564-574` flags any named direct child of svchost.
The real captures contain many expected-looking Windows service descendants.
These have not been independently classified as all benign, but their volume and
nonspecific reasoning make finding count an invalid proxy for attack detection.
The key Ramnit process is not prioritised, and there are no dedicated malfind,
psscan discrepancy or process/network corroboration rules in this baseline.

### P1 — Linux and Android artifact coverage

The main artifacts needed for Insider and The Crime remain unsupported. Those
cases are ingestion compatibility tests, not successful automatic investigations.
Do not add expected answer strings to detection logic to make a lab score pass.

### P2 — report accounting and presentation

Reveal's inventory says **1,872 events** (parsed pre-dedup) while its timeline has
**637**. These are different metrics and must be explicitly labelled, especially
while identity collisions are present. The plugin table is legible and lists
actual row counts; snapshot/heuristic caveats are visible. The existing Analysis
Runs UUID column still wraps into tiny fragments, wasting space.

## Acceptance checks and next steps

The custom `validation-checks.json` has **41 selected checks: 36 pass, 5 fail**.
The failures are two region-preservation checks and three service-name-preservation
checks. This is a bounded wrapper/indicator/fidelity check set, **not** a score for
all lab questions or forensic completeness. Android coverage/detection issues above
are additional assessment findings, not silently counted as passes.

1. Add failing regression tests for object-specific memory identity, then fix
   deduplication without changing existing non-memory evidence identity. Include
   region bounds, service identity and full socket endpoints; preserve source rows.
2. Reimport these three memory cases into fresh cases and rerun the same comparisons.
3. Tune lineage with corroboration and add memory-specific rules, retaining the
   distinction between an indicator and a confirmed malicious verdict.
4. Add Linux shell/auth and Android SQLite/WAL parsers if cross-platform coverage
   is in scope; otherwise make unsupported scope prominent in the automatic report.
5. Still obtain a real NTFS E01/raw acquisition for item-3 acceptance. This corpus
   does not validate raw partition/NTFS reading merely because it contains AD1.
