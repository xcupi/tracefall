# SQL Server forensics — phase 1 core

This phase is offline, deterministic **text-log and recorded instance configuration** support. It does not connect to SQL Server, attach databases, or execute SQL. Windows residuals, SQL Audit/XE decoding and SQL-to-Windows correlation are separate workstreams, not coverage supplied by this phase.

## Implemented inputs

| Evidence | Detection and output | Limits |
|---|---|---|
| `ERRORLOG`, `ERRORLOG.n` | Name plus recognizable SQL content in the initial 512 bytes; `mssql@1`, artifact `mssql_error_log` | English SQL message recognition; plain text only |
| `SQLAGENT.OUT`, `SQLAGENT.n` (also copied `SQLAGENT.OUT.n`) | Name plus timestamp / marker / bracketed message-number layout; `sqlagent@1`, artifact `sql_agent_log` | Agent messages are not complete job history |
| SOFTWARE hive | `Microsoft\Microsoft SQL Server\Instance Names\SQL`, direct `<instance-id>\Setup`, `<instance-id>\MSSQLServer\Parameters`; artifact `sql_instance_configuration` | Native registry view; not transaction-log replay or observed execution |
| Application EVTX / EvtxECmd CSV | Provider `MSSQLSERVER`, `MSSQL$<instance>`, `SQLSERVERAGENT`, or `SQLAgent$<instance>` **and** channel Application | SQL-provider messages, not an ID-only catch-all; no complete SQL Audit mapping |

Text input is bounded to 64 MiB per source. UTF-8 (optional BOM) and UTF-16LE **with BOM** are decoded. Invalid UTF-8, odd UTF-16 length and invalid surrogate sequences fail rather than silently replacing evidence characters. Compressed logs, UTF-16BE and BOM-less UTF-16 are not claimed as supported formats. Discovery can abstain when the initial sniff has no recognizable SQL record; an arbitrary or empty file named ERRORLOG is not SQL evidence.

## Exact semantics

* Every timestamp-prefixed engine/Agent record becomes its own event. Physical continuation lines stay with the preceding record, with the first physical line as `SourceReference` (`line:N`). A separate timestamped error header and login line remain separate records: no unproven joining of state or severity across records.
* Zone-less timestamps are **not UTC**: `Timestamp` remains zero, `Extra.timestamp_local` preserves the original full text, and `timestamp_basis` explains that no offset was recorded. No acquisition time, mtime, examiner zone or current date supplies missing information. An explicit RFC3339-compatible offset (including Z) is a true instant; its original stamp remains in `timestamp_original`. Agent's usual format has no offset.
* The original source file remains the byte-level evidence. Paired RawEvidence contains the decoded source record with its original spacing, line endings and continuations; normalization does not redact or rewrite it. The decoding BOM is not part of the first record's text. Unmatched preamble before the first timestamped record produces no event; it remains in the original source file.
* `Extra` retains message, SQL source token, recorded error number/severity/state, login/client, Agent marker/message ID and SQLSTATE when present. A message beginning `Login failed for user` or `Login succeeded for user` (optionally following Agent's `SQLServer Error: N,` prefix) supplies an explicit outcome. A quoted login phrase inside a SQL statement does not. An outcome-less mention of a login stays `sql_message`; a numeric text error header alone does not fabricate a login outcome.
* A unique recorded `Server name is 'host\instance'` supplies text-log instance attribution, with a recorded-server-name basis. Conflicting recorded server names leave attribution unknown. Directory names and the parser's absolute server path supply no instance or host identity. Without parse context, no absolute source path is copied into event identity.
* Registry mapping values name their recorded instance and instance ID. Setup values require a mapped engine instance ID or the canonical MSSQL instance-ID shape, avoiding shared-component Setup keys; custom orphan Setup keys without a mapping are not interpreted. Parameters are structurally scoped to MSSQLServer. Setup/Parameters values join to a name only through an unambiguous mapping in the same hive; an absent or ambiguous mapping stays unknown. Each value retains its key/name/data, raw typed value bytes (hex), and key last-write metadata if available. These events stay undated configurations, `records_execution=false`: a key's last write is not a SQL startup, install, query, or job execution time.
* Application normalization preserves every supplied named/positional data field under `sql_data.*` and a deterministic `sql_record_data` representation. It does not guess positional insertion-string roles. Named LoginName/ClientIP/DatabaseName/ErrorNumber/Severity/State are retained when present. An explicit named Message uses the same English field extraction as the text parser. Engine provider Event ID 18456 records failure; the same ID from another provider or channel is not claimed. Other SQL IDs remain messages unless actual text establishes an outcome. A CSV-only rendered description is retained with known command-secret forms redacted, excluded from identity; raw input and insertion strings are unchanged. This is not comprehensive SQL-secret redaction.
* Text identity includes evidence-relative source path, line reference, original local reading/message, SQL source/Agent message ID and instance. Thus distinct tied lines survive while exact same-path recollection deduplicates. SQL configuration identity includes value data/instance ID. SQL Application identity adds supplied insertion data to the existing Windows channel/record identity. These changes are scoped to SQL artifacts/events; unrelated historical hashes are unchanged. Persisted API tests verify representative counts and separate observation/raw IDs across recollection. Renamed rotations or differently rendered exports are not promised to deduplicate against text logs. Old imports that previously omitted SQL messages require a fresh import; this feature does not reconstruct lost events.

## Not implemented / NOT-VERIFIED

Binary `.xel`, `.sqlaudit`, `.trc`, database `.mdf`/`.ndf`/`.ldf` decoding, SQL transaction reconstruction, live server queries, SQL-to-Windows execution attribution and complete job history are **not implemented by phase 1**. NTFS `$LogFile` is not a SQL transaction log. A configured startup argument or an Agent message does not establish an OS process or a successful job step.

Tests use neutral synthetic text, generated registry hives and generated EVTX records. No real SQL Server evidence corpus, independent EVTX decoder comparison, Windows/SQL version matrix, localized message corpus, WOW6432Node/legacy instance schema or rendered-browser interaction was verified for this phase. The API test exercises real discovery/import/timeline/provenance handlers and SQLite persistence using synthetic trees. Focused package/UI tests, build and vet are the verification gates; the repository-wide suite is intentionally not run in this isolated workstream.

## Format sources

* Microsoft, [sys.sp_readerrorlog](https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sp-readerrorlog-transact-sql?view=sql-server-ver17): ERRORLOG numbered rotations and engine versus Agent sources.
* Microsoft, [MSSQLSERVER_18456](https://learn.microsoft.com/en-us/sql/relational-databases/errors-events/mssqlserver-18456-database-engine-error?view=sql-server-ver17): failure semantics and Date / Source / Message example, error/severity/state and client text.
* Microsoft, [sp_cycle_agent_errorlog](https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sp-cycle-agent-errorlog-transact-sql?view=sql-server-ver17): actual Agent rotation names `SQLAgent.1`, `.2`, etc.
* Microsoft Q&A, [Agent log format example](https://learn.microsoft.com/en-gb/answers/questions/973505/sql-server-agent-not-running): observed timestamp / `?` or `!` / `[message-id]` layout and SQLSTATE. This is a public example, not a normative binary/encoding specification or a validation sample committed to this repository.
* Microsoft, [Windows Application log](https://learn.microsoft.com/en-us/sql/relational-databases/performance/view-the-windows-application-log-windows-10?view=sql-server-ver17): channel and default/named engine/Agent providers.
* Microsoft, [file locations and registry mapping](https://learn.microsoft.com/en-us/sql/sql-server/install/file-locations-for-default-and-named-instances-of-sql-server?view=sql-server-ver17): distinct instance names/IDs and the Instance Names mappings.
* Microsoft, [sys.dm_server_registry](https://learn.microsoft.com/en-us/sql/relational-databases/system-dynamic-management-views/sys-dm-server-registry-transact-sql?view=azuresqldb-current): registry configuration/installation information and startup Parameters, not offline proof of execution.
