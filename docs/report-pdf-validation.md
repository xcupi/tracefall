# Report PDF validation

Scope: the existing built-in PDF path only (`GET /api/cases/{id}/report.pdf`
-> `Service.ReportPDF` -> `report.RenderPDF`, headless Chrome/Chromium).
No other renderer is used and none may stand in for it. This checks a
bounded synthetic case; it says nothing about the PDF of a large real case.

## What the PDF is

- Derived from `report.html` (same bytes the manifest hashes). It is not
  byte-reproducible (the browser embeds creation times); compare the HTML
  semantically, never invent a cross-renderer hash.
- It carries no attachments. `cited-events.json`, `correlations.json`,
  `timeline.csv`, `findings.csv` and `manifest.json` exist only in
  `report.zip`; those are the sensitive evidence-bearing files. The
  redacted command text in the HTML/PDF is a report copy, not a scrubbed
  original.
- Headless Chrome runs with its own sandbox enabled (no `--no-sandbox`).
  If the sandbox cannot start the render fails; it is not retried another way.
- `--no-pdf-header-footer` is set: there is no per-page header or footer.
  The "Generated by ..." footer appears once, at the end of the document.
- A missing browser gives `ErrNoRenderer` (HTTP 501). A browser crash gives
  an error, never an empty PDF or an HTML substitute.

## Automated checks

    go test ./internal/report -run '^TestPDF_' -count=1 -v

Skipped when Chrome/Chromium or Poppler (`pdftotext`, `pdfinfo`) is absent.
Set `TRACEFALL_PDF_PROOF_DIR=/abs/dir` to keep each test's PDF and text.

They assert, on a neutral synthetic report (100 events, 40+ pages, long
paths and commands, Indonesian punctuation and non-Latin text):

- `%PDF-` magic, non-trivial size, many pages, A4 box, no text outside it;
- full 64/128-hex hashes, event/attachment hashes, long path and command
  tails, finding/correlation numbers, footer and non-Latin text survive
  (checked in `pdftotext -raw` order, since `-layout` interleaves wrapped
  cells);
- an undated count (unknown) stays distinct from a measured zero
  (`0 failed to parse`, `0 duplicate`) and a non-zero measurement is not
  shown as zero; an unrecorded time zone says "not recorded" with its reason;
- attachment file names are not split mid-word;
- a cancelled render leaves no Chrome process and no staging directory;
- a missing browser is an honest error with no output;
- a too-deep `TMPDIR` fails with an error that names the cause.

## Known operational constraint

Chrome binds a unix socket under `TMPDIR` (about 107 bytes in `sun_path`).
With a deep `TMPDIR` it aborts with `Socket path too long`; `RenderPDF`
now reports that line and the remedy. The HTTP response stays generic; the
detail is in the server log. Give the server a short `TMPDIR`.

## Manual compiled-binary check (loopback, synthetic)

1. `go build -o bin/tracefall ./cmd/tracefall`.
2. Copy `testdata/synthetic_case` to a scratch directory; start the binary
   on `127.0.0.1` with a scratch `--db`/`--data-dir`, a short `TMPDIR` and
   `TRACEFALL_EVIDENCE_ROOTS` set to the copy. No provider, VirusTotal key
   or credentials are needed.
3. Create a case, ingest the path, import the discovered files, analyze
   (mutating calls need any non-empty `X-Tracefall-Client` header).
4. Request `report.html`, `report.pdf`, `report.zip`; expect 200 and
   `application/pdf` with `%PDF-`.
5. `pdfinfo`, `pdftotext`, `pdftoppm -r 80 -png` first, middle, long-table
   and last pages and look at them; do not accept a string match alone.
6. Stop the server and confirm the port is closed.

## Not verified

A full-size real-case PDF (hundreds of findings, tens of thousands of
events). Chrome holds the whole document in memory while printing; the
reporting path is not constant-memory.
